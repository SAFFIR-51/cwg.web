# 풀리프 메인 페이지 — 디자인 의도와 코드 변경 기록

작성일: 2026-10-02

대상: 홈페이지 `/`의 첫 화면과 이어지는 메인 랜딩 전체

기준: 현재 작업 트리의 구현과 사용자 피드백. 개별 커밋 이력이 아닌, 최종 디자인 결정과 주요 변경 사항을 정리한 문서다.

## 1. 핵심 컨셉: 생활의 가치를, 한 번 더

이미 가진 일상에서 새로운 혜택을 발견한다는 메시지를 중심으로 디자인했다. 첫 화면은 브랜드의 인상을 전달하고, 아래로 내려가면 실제 서비스·참여·멤버십·생활권 혜택을 차례로 보여준다.

카카오페이 레퍼런스에서는 넓게 펼친 이미지, 일정한 세로 기준선, 큰 제목과 절제된 설명, 원형 화살표의 배치 원칙을 참고했다. 실제 색상, 앱 화면, 캐릭터, 멤버십 카드와 카피는 풀리프의 자산과 서비스에 맞췄다.

### 뫼비우스 띠를 모티브로 한 타원 선

첫 화면을 가로지르는 원형·타원형 선은 단순한 장식이 아니다. 사용자가 설명한 디자인 의도는 **뫼비우스 띠를 통해 ‘한 번 더’를 연상시키는 것**이다.

- 끝처럼 보이는 지점이 다시 시작으로 이어지는 흐름을 표현한다.
- 일상이 한 번의 소비나 사용으로 끝나지 않고 새로운 가치로 이어진다는 메시지를 보조한다.
- 화면 밖까지 이어지는 큰 곡선으로 연결감과 연속성을 만든다.
- 세로 기준선이 화면의 질서를 잡고, 곡선은 그 위에서 브랜드의 의미를 전달한다.

**디자인 모티브와 기하학적 구현은 구분한다.** 현재는 실제로 꼬인 3D 뫼비우스 띠나 무한대 기호를 렌더링한 것이 아니다. `border-radius: 50%`의 큰 CSS 타원을 회전하고 화면 밖으로 확장해, 그 연속성의 이미지를 추상적으로 표현한다. 따라서 이 요소를 설명할 때는 ‘뫼비우스 띠를 모티브로 한 순환 곡선’이라고 표현한다.

관련 코드: [Hero 구성](../components/PayLanding.js), [`.pay-hero-outline` 스타일](../styles/pay-landing.css).

## 2. 첫 화면 디자인과 구현

### 2.1 배경 이미지와 가독성

현재 배경은 [`main-hero-3.png`](../public/images/main-hero-3.png)다. 사람들의 일상 장면과 블루 포인트를 유지하고, 그 위에 짙은 오버레이를 얹었다. 왼쪽 문구 영역을 상대적으로 더 어둡게 만들어 흰색 제목과 다운로드 버튼이 배경에 묻히지 않도록 했다.

```css
.pay-hero {
  background: #315879 url('/images/main-hero-3.png') center / cover no-repeat;
}

.pay-hero-aura {
  background: linear-gradient(
    90deg,
    #08111db3 0%,
    #08111d8c 50%,
    #08111d6b 100%
  );
}
```

배경은 영상이 아니라 정적 이미지이며, 오버레이·곡선·세로선은 코드로 구현했다. 일시정지·전체화면 버튼, 첫 화면의 별도 부유 아이콘, `FULL LIFE, ONE MORE.` 보조 문구와 스크롤 안내 문구는 현재 Hero 마크업에서 제외했다.

### 2.2 순환 곡선과 기준선

데스크톱의 곡선은 다음 형태다.

```css
.pay-hero-outline {
  left: -12%;
  top: 11%;
  width: 125%;
  height: 74%;
  border: 1px solid #ffffff30;
  border-radius: 50%;
  transform: rotate(-22deg);
}
```

모바일에서는 폭을 `200%`, 왼쪽 위치를 `-50%`로 조정해 좁은 화면에서도 큰 흐름이 이어지도록 한다. 세로 기준선은 `#ffffff26`으로 표현한다. 두 선 모두 장식 요소이므로 `aria-hidden="true"`와 `pointer-events: none`을 사용한다.

### 2.3 한 화면을 꽉 채우는 높이

이전에는 데스크톱에 `min-height: 720px`, `max-height: 1200px`, 모바일에 `min-height: 760px`, `max-height: 1000px` 제한이 있었다. 큰 화면에서는 아래쪽이 남고, 작은 화면에서는 첫 장면이 화면 높이를 초과할 수 있었다.

현재는 고정 최소·최대 높이를 없앴다.

```css
.pay-hero {
  width: 100%;
  height: 100vh;
  height: 100svh;
  height: 100dvh;
  min-height: 0;
  max-height: none;
  overflow: clip;
}
```

지원되는 마지막 단위가 적용된다. `dvh` 지원 브라우저에서는 모바일 주소창 등으로 달라지는 현재 화면 높이에 대응한다. 헤더는 배경 위에 고정 배치하므로 Hero 높이에서 헤더 높이를 별도로 빼지 않는다.

이미지의 `cover`는 **비율을 유지하면서 영역을 빈틈없이 채우는 방식**이다. 화면 비율에 따라 사진 가장자리는 일부 잘릴 수 있으며, 전체 사진을 모두 표시하는 `contain` 방식은 아니다.

### 2.4 제목·설명·다운로드 버튼

- 제목: “생활의 가치를, / 한 번 더.”
- 설명: “쿠폰부터 티켓까지, 일상이 혜택이 되는 풀리프”
- 행동 유도: 기존 App Store·Google Play 배지 컴포넌트 재사용.
- 데스크톱: 제목 왼쪽을 콘텐츠 기준선에 맞추고, 시선이 머무는 화면 중하단에 배치.
- 모바일: 좌우 `24px` 여백을 두고 아래쪽을 기준으로 배치.
- 높이 `600px` 이하: 제목 크기·설명 여백·배지 높이를 줄여 낮은 가로 화면에서도 헤더와 버튼이 겹치지 않도록 보정.
- 모바일 하단 위치에는 `safe-area-inset-bottom`을 고려.

배경 이미지, 문구, 다운로드 경로를 새로 바꾸지 않고 화면 크기 대응만 조정했다.

### 2.5 헤더와 전체 메뉴

홈페이지 전용 `PayHeader`를 적용했다. 첫 화면 최상단에서는 투명 배경과 흰 로고·메뉴를 사용하고, 스크롤이 `40px`를 넘으면 흰 배경과 어두운 글자로 전환한다.

전체 메뉴는 네이티브 `<dialog>`로 열고, 메뉴가 열린 동안 배경 스크롤을 잠근다. 닫기와 포커스 복귀 처리를 포함하며, 모바일에서는 가로 메뉴 대신 전체 메뉴 버튼을 사용한다.

## 3. 아래로 이어지는 페이지 구성

현재 읽기 순서는 다음과 같다.

1. 첫 화면: 브랜드 메시지와 앱 다운로드
2. 서비스 개요: “일상의 모든 혜택 한 번 더 모아요”
3. ONE MORE와 낙첨 ONE MORE
4. 오늘의 한 표와 경품 추첨
5. 가입 보너스와 매일의 포인트 혜택
6. 놀이터: 넘버 센스·번호 만들기·럭키 스코어
7. FULIF+ 멤버십
8. FOUND AI 생활권 혜택
9. 브랜드 파트너
10. 풀리프가 지키는 네 가지 약속
11. 풀리 캐릭터 소개
12. 앱 다운로드 마무리와 푸터

### 3.1 이미지와 문구의 공통 정렬

중앙 콘텐츠 폭과 바깥 여백을 CSS 변수로 관리한다.

```css
--pay-gutter: max(32px, calc((100% - var(--pay-content)) / 2));
```

넓은 이미지 섹션은 `바깥 여백 / 왼쪽 열 / 오른쪽 열 / 바깥 여백`의 4열 그리드를 사용한다. 이미지는 화면 가장자리까지 뻗고, 문구는 중앙 콘텐츠 기준선에 맞춘다. 문구에는 별도 안쪽 여백을 두어 기준선에 붙어 답답하게 보이지 않도록 했다.

큰 화면에서는 콘텐츠 폭을 `1280px`, 화면 폭 `1700px` 이상에서는 `1400px`로 확장한다. 주요 앱 이미지 영역도 데스크톱에서 `600px` 높이로 키워 지나치게 작게 보이지 않게 했다. 모바일은 한 열로 전환한다.

### 3.2 서비스 화면 위의 보조 요소

앱 화면이 주인공이 되도록 아이콘 카드와 말풍선을 축소했다. 내 쿠폰·내 티켓·쿠폰 기부 카드 3개는 화면 아래쪽으로 이동했다.

| 구간 | 카드 그룹의 위쪽 위치 | 카드 높이 |
| --- | --- | --- |
| 모바일, 폭 767px 이하 | 300px | 86px |
| 기본/중간 폭 | 380px | 104px |
| 데스크톱, 폭 1200px 이상 | 460px | 112px |

문구 박스는 넓게 늘어나는 형태 대신 `width: max-content`와 `max-width: 84%`로 문장 길이에 맞췄다. 기존 문구는 유지하고 배경 화면을 가리는 면적을 줄였다. 카드 아이콘은 기존 SVG를 사용한다.

### 3.3 포인트 혜택과 놀이터

가입 보너스 배너와 아래 혜택 카드 전체를 하나의 옅은 블루 배경으로 묶었다. 보너스 설명과 시작 링크는 유지하고, 오른쪽 포인트 이미지만 작게 조정했다.

포인트 혜택은 데스크톱에서 4개를 한 줄에 표시한다. 폭 `1023px` 이하에서는 2개, `767px` 이하에서는 1개씩 보이는 가로 스크롤 구성이다. 자동 재생은 없고, 이전·다음 버튼과 좌우 방향키로 이동할 수 있다.

놀이터는 각 이미지의 옅은 배경색을 설명 영역까지 이어 세 카드가 하나의 완성된 단위로 보이게 했다. 하단 안내 칩은 배경과 보더를 통일했고, ‘자세히 보기’ 문구 대신 오른쪽 끝에 작은 원형 화살표를 배치했다. 링크의 접근성 이름은 서비스별로 유지한다.

### 3.4 FULIF+ 멤버십

멤버십은 딥 네이비 배경, 절제된 블루 하이라이트, 큰 워드마크로 구분했다. 오른쪽에는 사용자가 지정한 기존 가로형 멤버십 카드 디자인을 재사용했다.

이 카드는 단순 이미지 삽입이 아니라 `.plus-pass`, `BrandSymbol`, 텍스트와 CSS로 구성된다. 기존 [story.css](../styles/story.css)의 카드 스타일을 재사용하고 홈페이지 범위에서 크기와 그림자를 조정했다. 혜택은 숫자 중심으로 정돈하고, 가격·자동 결제·무료 체험·응모권 동일 확률 안내는 남겼다.

### 3.5 FOUND AI와 브랜드 파트너 이미지 교체

복잡한 실제 매장 사진 대신 블루·화이트 톤의 3D 이미지를 새로 생성했다.

| 영역 | 현재 자산 | 디자인 의도 |
| --- | --- | --- |
| FOUND AI | [found-neighborhood-3d-v2.png](../public/images/bright/found-neighborhood-3d-v2.png) | 동네 상점과 주유소, 앱 화면을 위한 중앙 여백 |
| 브랜드 파트너 | [partner-rewards-3d-v2.png](../public/images/bright/partner-rewards-3d-v2.png) | 선물 상자·쇼핑백·쿠폰으로 함께 만드는 혜택 표현 |

내장 이미지 생성 도구로 제작했으며, 프롬프트는 [LOWER_LANDING_IMAGES.md](LOWER_LANDING_IMAGES.md)에 기록했다. 이전 사진은 삭제하지 않았다. 현재 홈페이지의 두 이미지에는 Next.js `Image`의 `quality={95}`와 반응형 `sizes`를 적용했다.

FOUND AI의 실제 앱 화면은 이미지에 합성하지 않고 기존 `Device` 컴포넌트를 위에 배치한다. 장소 핀은 왼쪽 상점·카페, 오른쪽 주유소 이미지에 맞게 연결했다. 해당 두 섹션의 제목 위 장식 아이콘은 제거했지만, 사진 위 장소 핀은 유지한다.

### 3.6 하단 마무리

신뢰 안내는 옅은 배경 위의 4개 카드로 정리했다. 풀리 소개는 왼쪽 설명과 오른쪽 캐릭터 패널로 구성하며, 오른쪽 패널은 중앙 세로선·오른쪽 끝·아래 보더에 여백 없이 닿도록 했다. 패널의 `column-gap`, 하단 안내 위 `margin-top`, 모서리 반경을 제거한 것이 핵심이다.

마지막 다운로드 영역은 밝은 블루 그라데이션으로 마무리해 네이비 멤버십 이후 다시 사이트의 기본 톤으로 돌아온다.

## 4. 스크롤 애니메이션

요구사항은 ‘간격을 더 벌려 다음 내용을 밀어내기’가 아니라, **현재 보이는 내용에 집중한 뒤 스크롤 방향에 따라 다음 내용이 드러나는 것**이었다. 따라서 애니메이션을 위해 추가했던 화면 높이·여백은 되돌렸고, 모션 전용 CSS에는 레이아웃 간격 규칙을 넣지 않았다. 이전에 별도로 조정한 섹션 간 여백은 유지한다.

현재 구현은 [useLandingReveal.js](../components/useLandingReveal.js)의 `IntersectionObserver`를 사용한다.

- 화면의 관찰 영역 안으로 들어오면 `.pay-visible`을 추가한다.
- 관찰 영역을 벗어나면 클래스를 제거해 다시 숨긴다.
- 아래로 내릴 때와 위로 올릴 때 모두 반복한다. 한 번 등장하고 끝나는 방식이 아니다.
- 투명도는 `0.6초`, 이동은 `0.75초`, 이동 거리는 `28px`다.
- 화면 위로 벗어난 요소는 위쪽, 아래로 벗어난 요소는 아래쪽으로 이동하며 사라진다.
- 앱 화면과 관련 문구가 속한 `.pay-pair-column`, 가입 배너는 각각 묶어서 관찰해 중첩 애니메이션을 피한다.
- 상단 제외 영역은 `max(84px, 화면 높이의 12%)`, 하단은 화면 높이의 `18%`다. 높이를 기준으로 계산한 픽셀 값을 사용한다.

이는 스크롤을 강제로 고정하는 방식, 스크롤 스냅, 전체 페이지 슬라이드 전환이 아니다. 원래 문서 흐름을 유지하면서 요소의 등장·퇴장만 제어한다. 화면 높이에 따라 여러 요소가 동시에 보일 수 있다.

접근성 대응도 포함한다. 포커스가 있는 요소는 숨기지 않고, 키보드 포커스 진입과 해시 링크 이동 시 필요한 내용을 드러낸다. 모션 감소 설정에서는 전환 없이 표시하고, `IntersectionObserver`가 없거나 JavaScript가 실행되지 않아도 기본 콘텐츠가 보이도록 한다.

## 5. 사용자 피드백에 따른 정보 정리

메인 페이지가 상세 정책 문서처럼 길어지지 않도록 다음 항목을 홈페이지에서 덜어냈다.

- ‘한 번 더의 의미’ 같은 작은 부제목.
- ‘끝이 아니라, 다음의 시작’ 소개와 모으고·참여하고·발견해요 카드 묶음.
- 주요 네 서비스 제목 위 아이콘, 장문의 설명, 세부 적립 조건 패널.
- 놀이터 제목 아래의 별도 소개 문단.
- FOUND AI 아래의 추가 설명·약속 카드 묶음.
- 브랜드 파트너의 광고 카테고리·노출 화면·브랜드 수 통계.
- ‘쓰지 않을 쿠폰이, 누군가에게는 첫 선물이 돼요’ 독립 기부 섹션.

이는 모든 관련 기능이나 안내를 삭제했다는 뜻이 아니다. 포인트 혜택 카드의 쿠폰 기부, 네 가지 약속, 멤버십 결제 안내처럼 현재 남아 있는 내용은 보존했다. 상세 서비스 페이지를 같은 방식으로 삭제하거나 개편한 것도 아니다.

## 7. 검증 기록과 유지보수 기준

### 구현 작업에서 확인한 항목

이 문서 작성은 설명을 추가하는 작업이며, 아래는 직전 구현 작업에서 수행한 검증 기록이다.

- 최신 Hero 수정 후 `npm run build` 성공.
- `scripts/check-home-story.mjs`: 12개 챕터·40개 콘텐츠 항목, 앵커 중복 여부, 승인된 Hero 보존 검사 통과.
- `scripts/check-landing-reveal.mjs`: 양방향 반복, 그룹 처리, 해시 이동, 포커스, 모션 감소, 미지원 환경의 기본 표시, 정리 로직 검사 통과.
- Hero의 화면 높이를 2560×1271, 1440×900, 390×844, 320×568, 844×390 조건에서 확인. 각 조건에서 Hero 높이가 뷰포트 높이와 같고, 본문이 헤더 아래에 있으며, 다운로드 버튼 잘림과 가로 문서 넘침이 없음을 확인.
- 새 FOUND AI·파트너 이미지는 데스크톱과 모바일에서 표시·크롭을 확인.

위 확인은 사용한 브라우저와 테스트 크기 기준이다. 모든 모바일 기기와 브라우저의 실기기 검증을 완료했다는 의미는 아니다.

### 이후 변경 시 지킬 기준

- 순환 곡선은 브랜드 의미를 가진 요소다. 일반적인 장식 타원으로만 취급해 삭제하지 않는다.
- ‘뫼비우스’라는 의도와 실제 CSS 타원 구현을 혼동해, 구현되지 않은 3D 효과를 설명하지 않는다.
- Hero에는 고정 최대 높이를 다시 두지 않는다. `cover`의 크롭과 `dvh`의 높이 변화를 함께 확인한다.
- 스크롤 연출 요구를 큰 여백 추가로 대체하지 않는다. 양방향 재등장과 모션 감소 설정을 함께 확인한다.
- 배경 이미지 교체와 앱 화면·카피 변경을 분리한다. 새 생성 이미지는 원본 자산을 덮어쓰지 않고 버전 파일로 보관한다.
- 아이콘과 말풍선은 보조 요소다. 앱 화면을 다시 크게 가리지 않도록 크기와 위치를 점검한다.
- CSS는 불러오는 순서에 따라 덮어써진다. 수정 시 기본·하단·큰 화면·모션 규칙을 함께 확인한다.
- 이전에 제거한 소개·조건·통계 블록을 임의로 되살리지 않는다.

이번 문서 추가에서는 화면 코드나 디자인을 변경하지 않았다.
